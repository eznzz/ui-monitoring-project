# Monitoring Project — UI Constitution v1.0

## Главный принцип

**Monitoring Project Design System является единым источником UI-стандартов** для существующих frontend-приложений VDMS.

Утверждённая отправная точка — перенесённый оригинальный каталог компонентов. Не менять его основные визуальные и поведенческие решения произвольно.

## Обязательные правила

1. Единые токены в `tokens/tokens.css`; Primary 700 `#24518F` в Light и Primary 300 `#81B4F1` в Dark.
2. Все новые компоненты поддерживают обе темы, текстовый статус, клавиатурный фокус и мобильный экран.
3. Общие компоненты сначала добавляются в `components/` и документируются, затем повторно используются в модулях.
4. Не копировать стили отдельных UI-компонентов в модули и не менять значения токенов локально без обоснования.
5. Data Visualization развивается отдельно от форм и базовых контролов.
6. В этом репозитории разрабатываем **только frontend UI**. Сохранение данных и серверные процессы могут имитироваться mock-сценариями.
7. Технические имена `vms-*`, `--vms-*` и `vms-theme` временно сохранены для обратной совместимости; пользовательское название — **Monitoring Project**. Их переименование допустимо только с одновременным обновлением всех зависимостей.
8. Не заявлять полное соответствие WCAG или адаптивность на всех устройствах без фактических браузерных проверок.

## Критерии готовности UI-компонента

- Темы Light и Dark, default/hover/focus/disabled/error/loading (где применимо).
- Размеры 320, 360, 375, 390, 428, 768, 1024, 1440 px без наложений и потерянных действий.
- Клавиатура: Tab/Shift+Tab, Enter/Space, Escape и стрелки в применимых компонентах.
- Текст не обрезается критически; элементы не уходят за края экрана; таблицы имеют управляемую горизонтальную прокрутку.
- Масштабирование текста и `prefers-reduced-motion` учитываются.
- Новый или изменённый элемент документирован и показан в каталоге.

## Разделение UI

- **Foundations:** токены, шрифты, сетка и темы.
- **Components:** buttons, inputs, select, checkbox, badges, tabs, modal, toast, etc.
- **Patterns:** карточка записи, реестр, формы редактирования, фильтры, поиск, управление доступом.
- **Data Visualization:** графики, KPI, временные ряды, карты.

Для результатов исходного responsive-review см. [Mobile QA](mobile-qa.md).

## Функциональные границы

VDMS является единственным источником данных и логики. Демо имитирует ответы API, не добавляет новых продуктовых сущностей и не выполняет реальные операции.

## Обязательная базовая оболочка для всех административных экранов

**Корневой Dashboard Template** (`index.html`, `style.css`, `script.js`) — каноническая реализация общей оболочки приложения. При разработке новых страниц необходимо использовать его существующие структурные классы `app`, `sidebar`, `sidebar__nav`, `topbar`, `user-menu`, `content`, штатные обработчики burger, dropdown и переключения Light/Dark; нельзя создавать второй независимый Sidebar/Topbar со своей логикой.

Экраны `frontend/central-workspace/` и `frontend/tenant-console/` используют общий `frontend/shared/Shell.tsx`, оригинальные токены, CSS и script.js. Вспомогательные `modules/shared/ui.css` и `modules/shared/template.css` содержат **только дополнительные стили бизнес-панелей, шаблонов карточек, адаптивной компоновки и совместимости**, а не копию общей оболочки. Рефакторинг модулей не должен изменять эталонный оригинальный `style.css` и `script.js` без отдельного согласования.
