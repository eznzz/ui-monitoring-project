# Monitoring Project — архитектура frontend UI

**Статус:** архитектура разработки. Первичные экраны уже созданы в `modules/auth/`, `modules/platform/`, `modules/tenant/` и `modules/shared/`. Остальные каталоги из схемы — план, а не готовая реализация.

## Решение

Репозиторий `eznzz/ui-monitoring-project` — единый источник исходного кода всех UI-модулей. Исходный каталог компонентов `components/`, общие дизайн-токены `tokens/`, существующий Dashboard и опубликованное демо продолжают работать без перемещения.

Новые экраны организуются по функциональным модулям внутри `modules/`. Модуль не копирует глобальные токены и стили: он подключает общие компоненты, шаблоны и CSS, добавляя только предметную разметку и специальные стили.

**Область проекта:** HTML + CSS + JavaScript, Light/Dark, desktop/tablet/mobile и mock-данные. Backend, API, управление реальными базами и серверная аутентификация на данном этапе не реализуются.

## Слои интерфейса

1. **Foundations** — CSS-токены: цвета, типографика, радиусы, размеры и состояния. Текущий источник: `tokens/tokens.css`.
2. **Primitives / Components** — Button, Input, Select, Checkbox, Badge, Tabs, Modal, Toast, Date Range. Текущий каталог — эталон поведения и внешнего вида; пригодные для импорта реализации постепенно извлекаем в `shared/ui/`.
3. **Patterns** — Page Header, Toolbar, Search/Filters, Data Table ↔ Mobile Cards, пагинация, Empty/Loading/Error, Detail, Edit Form, Confirmation, File Upload.
4. **App Shell** — общая рамка приложения: sidebar, topbar, breadcrumb, page container, theme, responsive navigation. Реализация в `shared/shell/` должна исключить копирование полной разметки между страницами.
5. **Modules** — конкретные страницы, предметные названия, меню, mock-данные и локальные стили.
6. **Data Visualization** — отдельные chart/KPI-компоненты; бизнес-экраны импортируют их без копирования SVG-кода.

## Правила независимых страниц

- Модуль подключает общие файлы относительными путями. Для GitHub Pages project site нельзя полагаться на абсолютные URL вида `/tokens/...` без учёта префикса репозитория.
- В модульных файлах не определяются глобальные цветовые значения или альтернативная версия общего Input/Button.
- Доменное CSS именуется пространством модуля (например, `.core-vessel-*`), а общие компоненты — общим компонентным префиксом. Не создавать глобальные селекторы вроде `.primary` внутри новых модулей.
- Интерфейс работает без backend на локальных mock-данных; кнопки явно сообщают о демонстрационном характере действий.
- Каждый новый общий паттерн сначала документируется в каталоге, затем используется в нескольких модулях.
- Light/Dark и мобильное отображение — обязательные свойства, а не отдельные версии экранов.
- Табличное представление на больших экранах и карточное на мобильных получают данные из одного массива и делят фильтрацию, сортировку, выбор и пагинацию.
- Верстку существующей эталонной страницы не ломаем при извлечении компонентов.

## Первый этап — первичные экраны (реализован UI-прототип)

Вместо разработки прикладных модулей сначала утверждаем доступ и управление лицензированием:

- [`modules/auth/login.html`](../modules/auth/login.html) — демонстрационный вход.
- [`modules/platform/index.html`](../modules/platform/index.html) — `platform_db`: компании, отметка оплаты каждого из девяти модулей и включение только оплаченных модулей.
- [`modules/tenant/index.html`](../modules/tenant/index.html) — `tenant_db_000001`: первичная настройка компании (создание пользователей и базовые карточки судов).
- [`modules/shared/`](../modules/shared/) — локальные общие стили, shell и mock-состояние только для первичных экранов.

**Бизнес-правило:** все девять полноценных модулей оплачиваются по отдельности и включаются **только через платформу**. Создание пользователя и базовая карточка судна в компании — начальные действия до подключения платных модулей; расширенные Core/Auth ими не активируются. В интерфейсе tenant невозможно изменить лицензии.

Дальнейшая архитектура модулей остаётся планом, а не поручением их реализовать. Перенос общих решений из `modules/shared/` в общую библиотеку нужно согласовывать после приёмки начальных экранов. Подробности — [modules/README.md](../modules/README.md).

## Definition of Done для нового экрана

1. Общий App Shell и дизайн-токены; нет дублирующихся библиотечных стилей.
2. Light/Dark, адаптивность (320, 360, 375, 390, 428, 768, 1024, 1440 CSS px), рабочая клавиатурная навигация.
3. Содержательная Empty/Loading/Error демонстрация там, где сценарий требует.
4. Таблица или карточки используют единое состояние поиска, фильтров и пагинации.
5. Переходы между страницами рабочие на GitHub Pages; нет ошибок подключения ассетов.
6. Функциональность остаётся UI-only, любые mock-данные и имитации явно обозначены.
