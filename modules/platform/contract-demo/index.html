Границы и источники

Визуальная модель создана для согласования API-ориентированного пользовательского опыта. Это не новая реализация аутентификации, не backend и не работающий контроль доступа.

Разделение APIPlatform API: /internal/platform-admin/*; Tenant API: отдельное пространство /api/v1/*.
Права доступаТолько сервер определяет permissions. В этом макете роли — выбираемые тестовые фикстуры.
Создание компанииСоздание компании: requestId UUID v4 + code + name. Здесь нет ввода владельца или objectType — их нет в данном POST.
Редактирование черновикаРедактирование только draft с expectedRevision; 409 требует повторного чтения.
Активация и ReviewerЗаявка на активацию не означает, что компания provisioned или active. Reviewer — отдельный сценарий с серверным MFA.
Секреты и безопасностьНикаких реальных паролей, TOTP, токенов и секретов в localStorage или fixtures.
ИнформацияДемо не вызывает API. Документация: Central Platform API · Матрица соответствия (если принята в main).
