Вход / MFA

Визуальный макет с имитацией ответов. Ни один запрос не отправляется на сервер VDMS.

Режим: локальные фикстуры. Пароли, TOTP и токены здесь не обрабатываются.

Platform Login

Штатный контракт: POST /login → POST /access → GET /me. Требуются loginName, пароль и TOTP. В этом публичном демо ввод секретов отсутствует.

Заявки на активацию

GET /activation-reviews · отдельное право tenant.provision.approve. Одобрение требует другого Reviewer, свежих пароля и TOTP на реальном сервере.

В концепте решение имитируется без ввода пароля или TOTP, без серверного provisioning и без выдачи реальной лицензии.

Границы и источники

Визуальная модель создана для согласования API-ориентированного пользовательского опыта. Это не новая реализация аутентификации, не backend и не работающий контроль доступа.

  • Platform API: /internal/platform-admin/*; Tenant API: отдельное пространство /api/v1/*.
  • Только сервер определяет permissions. В этом макете роли — выбираемые тестовые фикстуры.
  • Создание компании: requestId UUID v4 + code + name. Здесь нет ввода владельца или objectType — их нет в данном POST.
  • Редактирование только draft с expectedRevision; 409 требует повторного чтения.
  • Заявка на активацию не означает, что компания provisioned или active. Reviewer — отдельный сценарий с серверным MFA.
  • Никаких реальных паролей, TOTP, токенов и секретов в localStorage или fixtures.

Демо не вызывает API. Документация: Central Platform API · Матрица соответствия (если принята в main).
