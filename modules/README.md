# Monitoring Project · первичные экраны (UI-only)

Все рабочие экраны находятся **в отдельном каталоге `modules/`**, эталонная библиотека `components/` и токены `tokens/` не изменяются.

## Экранный маршрут

1. [Вход](auth/login.html) — выбор платформы или компании исключительно для демонстрационного перехода (не реальная авторизация).
2. [Platform Admin](platform/index.html) — организация списка компаний, просмотр выбранной компании, создание компаний с **типом объектов**, вкладки **Подписка и модули** и **Лицензионные ключи**.
3. [Company Admin](tenant/index.html) — вкладки **Пользователи** (роли `office` и `vessel`), **Суда** и **Лицензии**.
4. [Ship Particulars](tenant/vessel.html) — отдельный редактор карточки судна по разделам исходного документа с 96 обычными полями, редактируемыми грузовыми помещениями и тремя отдельными итогами.

## Справочник типов объектов

Создание компании включает обязательный выбор **типов объектов**. Список отображается из центрального mock-справочника `MP.OBJECT_TYPES` в [shared/app.js](shared/app.js), отражающего будущий справочник `platform_db`. Сейчас есть **только `vessels`**. Состав типов задаёт платформа, компания не добавляет их самостоятельно. Это **не** лицензируемый модуль, а базовый тип данных, который предприятие может вести на старте.

## Первичная настройка компании

На первом этапе у компании есть только:
- создание пользователя с ролью **office** или **vessel**; для роли **vessel обязательно выбрать конкретное ранее созданное судно**; пароль и подтверждение пароля присутствуют в форме, но **не сохраняются** в публичном демо и не обеспечивают вход;
- добавление и редактирование карточки судна, если platform назначила тип объектов `vessels`.

Нельзя включить отдельные модули из tenant-интерфейса. В демонстрационном UI платформа **сама** отмечает оплату и подтверждает подключение модулей Core, Auth, Documents, Crewing, Supply, VMS, Performance, Reports и Sync. Правило лицензирования: **оплата на платформе → выдача ключа с датой окончания → ввод ключа компанией → запрос с датой → подтверждение платформой**. Администратор компании может лишь запросить подключение, не активировать его.

## Ship Particulars

Источник для набора полей — загруженный пользователем документ `Marta Reefer_Ship_Particulars.docx` (2 страницы). Подробный [список разделов, правил и особенностей данных](tenant/SHIP_PARTICULARS_FIELDS.md).

В публичный демо-репозиторий перенесены **только названия полей и структура**, не фактические контакты и сведения о конкретном судне. В форме не объединены расходящиеся цифры `Total Cargo Volume` и `TOTAL CBM` из исходника.

## Локальные mock-данные

Единый файл `shared/app.js` хранит демонстрационные `companies`, `objectTypes`, `modules`, `tenants`, `users`, `vessels` и записи `licenses` / `licenseRequests` в `localStorage` (`mp-ui-prototype-v1`). Предусмотрена миграция прежней структуры карточек судов и роль `office` по умолчанию для ранее созданных пользователей.

Это **не настоящие базы** `platform_db` и `tenant_db_000001`, не платёжный механизм и не система контроля доступа. Не вводите реальные пароли, контактные или коммерчески конфиденциальные данные.

## Responsive

- В Platform Admin: компании как список, отдельное рабочее пространство выбранной компании, вкладки вместо всех разделов одновременно.
- В Company Admin: основной контент переключается между пользователями и судами, формы пользователей открываются в диалоге, судно заполняется на отдельной странице.
- В Ship Particulars: компактная навигация по разделам, двухколоночные поля на больших экранах, одна колонка на мобильных; грузовые помещения отображаются таблицей на desktop и карточками на mobile.

## Проверка

Проверить вручную в GitHub Pages: создать компанию с `vessels`; открыть её; сначала создать судно, затем пользователя `vessel` с обязательной привязкой к этому судну; проверить пароль и подтверждение без сохранения учётных данных; открыть Ship Particulars; заполнить Ship's Name, IMO, несколько остальных полей, добавить 1A–4C, сохранить и повторно открыть; на платформе отметить оплату модуля, выпустить ключ с датой окончания, ввести его на стороне компании, проверить статус «Ожидает», одобрить запрос на платформе, затем отозвать ключ и проверить прекращение доступа. Проверить переключение тем и ширины 320–1440 px.

Фактические браузерные тесты на физических устройствах ещё необходимы.

## Новые UI-контроли

- **Ship's Type** — Select (Reefer, Bulk Carrier, Tanker, Container Ship, General Cargo, Ro-Ro, Passenger, Fishing, Gas Carrier, Offshore, Tug, Other); исторические значения карточек сохраняются при редактировании.
- **Compartments** — кнопка «Удалить» остаётся в пределах строки таблицы и мобильной карточки; на desktop таблица прокручивается по горизонтали.
- **Licensing** — прототипные ключи создаются только на платформе, содержат даты выпуска и окончания. Запрос и решение имеют собственные даты. Это **не настоящие лицензии и не механизм защиты**: все данные видны в `localStorage`.

## Главные страницы административных кабинетов

По умолчанию `modules/platform/` и `modules/tenant/` открывают **Dashboard** с информационными плитками, а не формы и таблицы. Боковое меню и плитки ведут в **уже существующие** разделы, не создавая дубликатов:

- Platform: Главная (`#dashboard`), Компании (`#companies`), Подписка и модули (`#modules`), Лицензионные ключи (`#keys`), Правила подключения (`#principles`).
- Company: Главная (`#dashboard`), Пользователи (`#users`), Суда (`#vessels`, когда разрешены platform), Лицензии и запросы (`#licenses`).
- В dashboard платформы показываются количества компаний, оплаченных модулей, действующих подключений и ожидающих запросов; в dashboard компании — пользователей, судов, действующих подключений и ожидающих запросов.
- Данные плиток читаются из общего mock-состояния, обновляются после действий на той же странице и после изменения данных в другой вкладке браузера.
- Маршруты реализованы хешами в рамках существующих страниц, поэтому ссылки работают без дополнительных правил GitHub Pages.

## Грузовые помещения: единый адаптивный вид без scrollbar

Исходная широкая таблица помещений больше **не создаётся**. Каждое помещение отображается полноценной карточкой с восемью редактируемыми полями и кнопкой удаления. Карточки перестраиваются по доступной ширине, не требуют горизонтальной прокрутки ни на desktop, ни на mobile. Структура хранения `holds[]`, идентификаторы полей и функциональность добавления шаблона 1A–4C сохранены.
