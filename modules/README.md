# Monitoring Project — актуальные демонстрационные экраны

**Статус:** UI-only, HTML/CSS/JS, mock/localStorage. Это не настоящая авторизация, HTTP API, PostgreSQL, RBAC или платёжная система. Эталон Dashboard Template неизменен.

## Сценарии

1. [Login](auth/login.html) — демонстрационный выбор кабинета Platform/Tenant (не реальный вход).
2. [Platform Admin](platform/index.html) — централизованный Object Type (пока только Vessels), создание компании с уникальным e-mail первого Owner, архив/восстановление, отдельная системная лицензия и ручные подписки на модули с Fleet 3/5/10/30/50/Unlimited.
3. [Company Admin](tenant/index.html) — Office/Vessel, множественные назначения активных судов, независимые разрешения на модули, реестр судов со статусами, назначения активных судов модулю и необязательные обращения.
4. [Ship Particulars](tenant/vessel.html) — подробная анкета (96 полей, грузовые помещения, 3 итога). Обязательны только Ship's Name и IMO. Новое судно **inactive**, ручное включение отдельно.

## Объекты и миграция

**Platform** владеет каталогом Object Types; Super Admin при создании компании выбирает **один** тип, пока vessels. **Tenant** хранит экземпляры объектов выбранного типа, историю и связи. Object ID не зависит от IMO. Trucks/Bikes пока не реализованы.

Ключ localStorage сохранён: **mp-ui-prototype-v1**; версия данных — 5. Старые tenants[id].vessels мигрируют в tenants[id].objects, привязки по user.vesselImo — в user.objectIds. Исторические суда мигрируют как active, **новые** создаются inactive. Старые ключи лицензий остаются в legacy-массиве, но не создают подписки автоматически. Пароли демо-форма больше не запрашивает.

Система лицензий в mock: company.systemLicense отдельно от company.modules[moduleId] с датами, Fleet cap и списком объектов. Считать места только по **активным** назначенным объектам конкретного модуля; связи выключенных судов сохранять. Обращения необязательны и не включают модули.

Данные экранов читаются/сохраняются через [mock-adapter](services/README.md); он пока **синхронный**, не является готовым API-клиентом. Реальный backend сам проверяет tenants, permissions, subscriptions и object scopes.

## Проверки

1. Создать компанию с Vessels/owner e-mail; дубликат e-mail недопустим.
2. Создать судно, проверить inactive, включить, назначить несколько судов пользователю Vessel; Office может не иметь назначений.
3. Изменить IMO: ссылки по Object ID не должны теряться.
4. Архивировать судно, восстановить только в inactive; проверить сохранение истории и модульных связей.
5. В Platform выдать системную лицензию и подписку вручную, задать Fleet cap, затем назначить активные суда модулю в Tenant. Превышение лимита должно блокироваться.
6. Отправить необязательное обращение; проверить, что оно не включает подписку. Архивировать компанию без удаления tenant.
7. Проверить Light/Dark, адаптивность, клавиатуру и отсутствие изменений в эталонном шаблоне.

Не вводите реальные персональные, коммерческие данные или пароли в браузерное демо.
