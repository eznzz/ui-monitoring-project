# Monitoring Project · Primary Screens (UI-only)

Это **отдельный каталог первичных интерфейсов**. Утверждённый каталог дизайн-системы `/components/`, дизайн-токены `/tokens/` и исходный Dashboard в корне репозитория не перемещены и не переписаны.

## Начальные экраны

| URL в репозитории | Назначение |
| --- | --- |
| [`modules/`](index.html) | Переход на экран входа |
| [`modules/auth/login.html`](auth/login.html) | Экран входа: демонстрационный выбор роли |
| [`modules/platform/index.html`](platform/index.html) | Superadmin (`platform_db`): компании, оплата каждого модуля, подключение |
| [`modules/tenant/index.html`](tenant/index.html) | Администрирование компании (`tenant_db_000001`): пользователи и карточки судов |

Общие для этих экранов файлы: `shared/ui.css`, `shared/app.js`. Они используют `../tokens/tokens.css`, минимальные формы, кнопки и 6px-радиус исходного дизайн-стандарта. Все URL относительные, работают при публикации через GitHub Pages project site.

## Основное бизнес-правило

**Все девять модулей tenant-db: Core, Auth, Documents, Crewing, Supply, VMS, Performance, Reports, Sync — отдельно оплачиваются и могут включаться исключительно из `platform_db`.**

1. Суперадминистратор выбирает компанию и отмечает, что конкретный модуль **оплачен** (в демо это ручная имитация факта оплаты).
2. Только после отметки оплаты появляется возможность **включить** модуль этой компании.
3. Если отметку оплаты снять, включение немедленно сбрасывается.
4. Администратор компании **не видит переключателей оплаты или подключения**.
5. При первоначальной настройке без купленных модулей компания может **только создавать пользователей и заполнять базовые карточки судов**. Это стартовые действия, а не полный Core/Auth.
6. Экраны других модулей и рабочие функции в данном этапе намеренно отсутствуют. Их проектирование — отдельные последующие задачи.

## Демонстрационное состояние

- `platform_db` и `tenant_db_000001` — **концептуальные имена интерфейсных областей**, а не реальные БД.
- Начально создана одна демонстрационная компания `tenant_db_000001`; ни один из девяти модулей не отмечен оплаченным или включённым.
- Суперадминистратор может создать дополнительные компании в демо и отметить оплату/включение модулей по каждой.
- Создание пользователей и заполнение/редактирование карточек судов работает с mock-данными конкретной компании.
- Данные макета сохраняются в `localStorage` браузера под ключом `mp-ui-prototype-v1`, чтобы можно было переключаться между экранами.
- Выбор роли на login **не является авторизацией**. Поля email/password **не проверяются, не отправляются и не хранятся**. Не вводите реальные учётные данные.
- `localStorage` — не надёжная система контроля доступа и не подтверждение оплаты. Любой пользователь браузера может изменить эти демонстрационные данные. Никакого реального security boundary пока нет.

## Первичная проверка

1. Перейти через `modules/` и выбрать роль Platform; убедиться, что открыта платформа.
2. В `platform/index.html`: выбрать компанию, отметить «Оплачено», включить модуль; снять оплату и убедиться, что модуль выключается.
3. Открыть `tenant/index.html` — переключателей лицензий здесь нет, только Users и Vessels.
4. Создать пользователя, затем карточку судна, отредактировать карточку; проверить сохранение при обновлении страницы.
5. Переключить Light/Dark и проверить mobile (320, 375, 390, 428, 768 CSS px); тест на реальном Safari/Chrome нужно проводить отдельно.

## Следующий процесс согласования

Утверждаем внешний вид и пользовательскую логику **этих трёх экранов**. Только после этого расширяем предметные экраны. Не создавать модули по собственной инициативе и не затрагивать эталонный каталог без отдельной задачи.
