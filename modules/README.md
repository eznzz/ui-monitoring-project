# Monitoring Project · первичные экраны (UI-only)

Все рабочие экраны находятся **в отдельном каталоге `modules/`**, эталонная библиотека `components/` и токены `tokens/` не изменяются.

## Экранный маршрут

1. [Вход](auth/login.html) — выбор платформы или компании исключительно для демонстрационного перехода (не реальная авторизация).
2. [Platform Admin](platform/index.html) — организация списка компаний, просмотр выбранной компании, создание компаний с **типом объектов**, вкладка **Подписка и модули**.
3. [Company Admin](tenant/index.html) — вкладки **Пользователи** (роли `office` и `vessel`) и **Суда**.
4. [Ship Particulars](tenant/vessel.html) — отдельный редактор карточки судна по разделам исходного документа с 96 обычными полями, редактируемыми грузовыми помещениями и тремя отдельными итогами.

## Справочник типов объектов

Создание компании включает обязательный выбор **типов объектов**. Список отображается из центрального mock-справочника `MP.OBJECT_TYPES` в [shared/app.js](shared/app.js), отражающего будущий справочник `platform_db`. Сейчас есть **только `vessels`**. Состав типов задаёт платформа, компания не добавляет их самостоятельно. Это **не** лицензируемый модуль, а базовый тип данных, который предприятие может вести на старте.

## Первичная настройка компании

На первом этапе у компании есть только:
- создание пользователя с ролью **office** или **vessel**; для роли vessel можно опционально указать созданное судно;
- добавление и редактирование карточки судна, если platform назначила тип объектов `vessels`.

Нельзя включить отдельные модули из tenant-интерфейса. В демонстрационном UI платформа **сама** отмечает оплату и включает отдельные лицензии для Core, Auth, Documents, Crewing, Supply, VMS, Performance, Reports и Sync.

## Ship Particulars

Источник для набора полей — загруженный пользователем документ `Marta Reefer_Ship_Particulars.docx` (2 страницы). Подробный [список разделов, правил и особенностей данных](tenant/SHIP_PARTICULARS_FIELDS.md).

В публичный демо-репозиторий перенесены **только названия полей и структура**, не фактические контакты и сведения о конкретном судне. В форме не объединены расходящиеся цифры `Total Cargo Volume` и `TOTAL CBM` из исходника.

## Локальные mock-данные

Единый файл `shared/app.js` хранит демонстрационные `companies`, `objectTypes`, `modules`, `tenants`, `users`, `vessels` в `localStorage` (`mp-ui-prototype-v1`). Предусмотрена миграция прежней структуры карточек судов и роль `office` по умолчанию для ранее созданных пользователей.

Это **не настоящие базы** `platform_db` и `tenant_db_000001`, не платёжный механизм и не система контроля доступа. Не вводите реальные пароли, контактные или коммерчески конфиденциальные данные.

## Responsive

- В Platform Admin: компании как список, отдельное рабочее пространство выбранной компании, вкладки вместо всех разделов одновременно.
- В Company Admin: основной контент переключается между пользователями и судами, формы пользователей открываются в диалоге, судно заполняется на отдельной странице.
- В Ship Particulars: компактная навигация по разделам, двухколоночные поля на больших экранах, одна колонка на мобильных; грузовые помещения отображаются таблицей на desktop и карточками на mobile.

## Проверка

Проверить вручную в GitHub Pages: создать компанию с `vessels`; открыть её; создать `office`- и `vessel`-пользователей; открыть Ship Particulars; заполнить Ship's Name, IMO, несколько остальных полей, добавить 1A–4C, сохранить и повторно открыть; через Platform включить и выключить оплату/доступ к отдельному модулю. Проверить переключение тем и ширины 320–1440 px.

Фактические браузерные тесты на физических устройствах ещё необходимы.
