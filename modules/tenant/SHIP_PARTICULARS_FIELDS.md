# Ship Particulars — исходный состав полей карточки судна

**Источник:** предоставленный пользователем `Marta Reefer_Ship_Particulars.docx`, 2 страницы. Для UI использованы **названия и группировка полей**, а не персональные/операционные значения конкретного судна. Форма доступна как `modules/tenant/vessel.html` и заполняется пустой для каждой новой записи.

## Структура редактора

| Раздел исходного документа | Количество простых полей |
| --- | ---: |
| Identification / Registration | 14 |
| Principal Dimensions / Tonnage | 14 |
| Cargo / Reefer | 12 |
| Compartments Capacity and Dimensions | 8 колонок на каждую строку |
| Cargo Gear / Machinery | 14 |
| Speed / Performance | 4 |
| Tank Capacities / Added Fields | 8 |
| Owner / Manager / Operator | 10 |
| Vessel Communications | 8 |
| Additional Fields Recommended for Chartering | 12 |
| **Всего простых полей** | **96** |

Дополнительно есть самостоятельные поля итогов `TOTAL CBM`, `TOTAL CBFT`, `TOTAL SQM` раздела Compartments.

**Колонки грузовых помещений:** Hold / Deck, CBM, CBFT, SQM, Height, Length, Width, Hatch.

Редактор позволяет добавить любое количество строк. Кнопка `Добавить 1A–4C` создаёт **пустые** строки с обозначениями 1A, 1B, 2A, 2B, 2C, 3A, 3B, 3C, 4A, 4B, 4C, соответствующими примеру на первой странице. Значения вместимости и размеров не проставляются автоматически.

## Точность по исходному документу

- При повторении исходных заголовков (`Outreach`, `Max Power`) для внутреннего идентификатора используются уточнения: cargo winches / provisional crane, main engine / shaft generator.
- Поля `Total Cargo Volume` и `TOTAL CBM` **разделены**. В исходнике значение общего объёма на первой странице и итог таблицы грузовых помещений различаются. В UI эти сведения не пересчитываются и не приводятся к единому значению без проверки первичного источника.
- `Consumption` и `Fuel Consumption - Sea` / `Fuel Consumption - Port` — разные строки источника. Они не объединяются.
- Значения (включая единицы `m³`, `cbft`, `kn`, `RPM`, `t`), диапазоны, составные размеры и пометки вроде `NIL`, `Not stated` сохраняются как свободный текст: на этом этапе формат не нормализуется.
- Данные владельца, контактных лиц, почтовые адреса, телефоны и почта не копируются из файла в публичный репозиторий. Это только структура ввода.
- `Ship's Name` и `IMO No.` обязательны в демо, IMO валидируется как 7 цифр. Остальные поля факультативны. Это **UI-решение прототипа**, а не утверждение о полноте обязательных полей морской регистрационной анкеты.

## Хранение и доступ

Карточки сохраняются как `{id, fields, holds, holdTotals, updatedAt}` в локальном `localStorage` демо в `tenants[tenant_id].vessels`. Содержимое не шифруется, не отправляется в backend, не синхронизируется между устройствами. Не вводить сюда реальные конфиденциальные персональные или коммерческие сведения.

Публичное демо не ограничивает технически доступ к данным: настоящая валидация прав и схемы данных потребуется при разработке backend за пределами текущего UI-only этапа.
